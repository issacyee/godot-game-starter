## 文档职责

- **指南**规定通用性质与选择依据，可以使用 Godot API 解释边界，不写某台机器的结果或某个游戏的规则。
- **简报**定义项目目标；**能力清单**回答选择了什么；**契约**记录状态所有权、默认接法、失败语义和验证方式。
- **代码**定义实际签名；**测试与产物报告**提供行为证据；**范围与限制**说明尚未覆盖的能力。文档存在不等于实现完成。
- **调参导航**统一发现设计参数，不与指南或简报维护第二份可编辑默认值。

“必须／禁止”表示边界约束，“默认／建议”允许按需求说明替代方案，“按需”不要求预先写空接口。实际代码与约定不一致时先报告差异，不能凭新指南擅自全项目重构。

共享文档只保留当前有效约定，不写工作轮次、本机信息、历史验收或开发过程。具体报告留在忽略入库的 `artifacts/`；不能把旧结果用于新源码。
