# 项目简报

## 定位

供小团队定制的 2D／3D 双路线起步模板，默认体验 2D。使用 Godot 原生节点、静态类型 GDScript、独立 GdUnit4 测试与 dev 导出工具，不作为公共运行时框架。

## 路线选择

当前 `starter-project.json` 登记为 `template`，同时维护两条示例路线。派生游戏开始前必须明确选择 `2d` 或 `3d`，在本简报写清路线、视角、移动方式、单位及理由，再按 [路线步骤](ROUTES.md) 登记并设置主场景；默认 2D 不替代选择。派生后只维护所选路线，另一条可保留参考，不自动删除。

## 示例玩法

在固定场地控制蓝色方块，靠近金色目标并激活；2D 为 XY 俯视，3D 为 XZ 平面，均支持进入、暂停／继续和重开。该交互仅演示规则与场景协作，不预设关卡、战斗或美术系统。

## 架构起点

规则由 RefCounted 持有，协调层连接语义输入与生命周期，所选路线的 CharacterBody2D／CharacterBody3D 唯一管理位置，表现适配器只更新显示。共享 Resource 是定义，规则接收启动校验后的数值；具体模块见 [CONTRACTS](CONTRACTS.md)，扩展原则见 [架构指南](guides/game-architecture.md)。

## 默认范围

- Windows x86_64、键盘、Compatibility 渲染；其他平台需另行选择与适配。
- 不包含联网、遥测、账号、存档／完整快照、跨平台确定性或正式发布流程。
- 验证覆盖技术正确性，不评价美术、趣味或主观手感。

基于模板创建游戏时，将本简报替换为项目目标、核心体验、成功／失败条件、内容规模、目标平台、范围外事项和验收标准；同时写清实际状态所有者与重要选型的理由／代价。按 [阶段路径](deriving-a-game.md) 逐步复核能力，不继承模板通过记录。
