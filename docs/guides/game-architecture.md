# 游戏逻辑架构

逻辑／表现分离是状态所有权与副作用边界，不是要求每个职责建一个目录或所有逻辑脱离引擎。默认用少量数据、规则方法、节点组合和直接调用解决当前游戏需求，不建立跨游戏框架。

## ARCH-01：先识别复杂性

先明确游戏采用 2D 还是 3D 及相应空间单位，再说明核心循环、权威状态、变化轴、实体规模、时间模型、输入复现和目标设备预算，再选模式。

| 实际问题 | 可用做法 | 不应顺带引入 |
| --- | --- | --- |
| 玩家、AI、测试共用规则 | 语义请求、结果枚举、必要时带类型动作数据 | 每动作一个对象、全局事件总线 |
| 多实例共享内容 | Resource 类型定义 + 独立实例状态 | 可变共享生命／冷却／位置 |
| 能力组合多变 | 节点／数据组合、小策略 | 深继承树或通用插件系统 |
| 有限状态转换 | 显式状态机或受约束字段 | 任意跳转的布尔集合 |
| 大量同构实体确为瓶颈 | profiler、批处理，必要时数据导向设计 | 无基准的 ECS／对象池重写 |

分离不能自动带来性能、回放、联网权威或跨平台确定性。

## ARCH-02：规则、协调、物理、表现与平台边界

```text
玩家／UI／AI／测试
        │ 语义意图
        ▼
     协调层 ──请求、数值观测、显式时间──> 规则
        │                                  │
        │ 方向／生命周期                   │ 结果、值视图、事实
        ▼                                  ▼
  Godot 物理节点 ──位置／碰撞观测──> 协调层 ──> 表现适配器
                                                    │
                                      Control／CanvasItem／Mesh／Camera／Audio

平台／资源边界：启动参数、加载、文件、窗口、捕获、导出身份
```

| 职责 | 拥有 | 禁止 |
| --- | --- | --- |
| 规则 | 回合／战斗等规则状态、不变量、规则计时和需要的随机进度 | Node／SceneTree、Input、UI、文件、系统时钟、渲染或音频设备 |
| 协调 | 初始化、语义动作翻译、调用顺序、生命周期接线、参数投影 | 另一份规则状态、再次决定接受／拒绝、复制物理 |
| 引擎物理 | 所选路线 CharacterBody2D／CharacterBody3D 的位置、速度与碰撞；物理世界和运动约束 | 让显示插值坐标回写碰撞，或再维护一套“纯规则坐标” |
| 表现 | 可见性、文案、动画、粒子、镜头和音效等可重建反馈 | 推进规则、改物理位置／速度、暂停 SceneTree、保存进度 |
| 平台／资源边界 | 真实设备、文件、启动、导入、窗口、捕获和身份 | 将平台分支散落在规则公式中 |

规则使用 RefCounted，可在 Godot 无头环境直接测试；仍依赖 Godot 运行时，不声称 GDScript 脱离引擎。数值／向量／容器不等于设备依赖。

**依赖方向**：协调可以引用规则、物理、表现和平台适配；规则不能反向引用这些模块。表现接收值视图和所需显示节点，不拿到完整协调器或规则写入口。逻辑职责不强制一职责一类；小型组合根可以接入平台服务，但需要扩展时按变化原因拆开，不造万能上下文。

## ARCH-03：请求、结果与事实分离

请求表达“希望执行”，结果表达接受或拒绝及原因，事实表达“已经发生”。玩家、UI、AI 和测试通过同一语义路径，不能各实现一份规则。直接方法与封闭 `match` 足够时不增加命令框架。

协调层可以从物理节点计算距离、碰撞结果或其他观测，传数值给规则；是否允许交互、伤害或奖励仍由相应规则决定。空间运动约束交给物理，不在规则中再次夹取坐标。正常拒绝默认不改变权威状态、不产生成功反馈；是否耗时／消耗资源或允许部分执行，必须明确并测试。

延迟动作需在执行时检查目标有效性，明确顺序、取消和过期语义。排队、序列化、撤销、网络和回放均是额外需求，不能由“有动作名”推导已具备。

信号可承载局部事实；先提交权威状态，再发信号。Godot 默认连接同步调用，应明确订阅与释放、回调顺序和重入约束；表现观察者不回调规则写入口。使用 deferred 连接或队列时需重新定义有效期与顺序。不能用一个“最后事件”覆盖一步中的多个重要事实。

## ARCH-04：表现读取，不拥有真值

- 持久显示从当前值视图投影，支持初始化、重开和显示重建；一次性音效／粒子消费成功事实，不靠按钮按下或节点消失猜测。
- 查询和呈现可以改变显示节点／临时缓存，但不推进规则、不修改输入或物理，不触发存储。省略或重复呈现不改变相同语义输入下的玩法结果。
- UI 信号将意图送给协调层；`_draw()`、镜头、材质、Tween 和动画结束回调不直接决定伤害、无敌或交互成功。影响玩法的时间／命中由规则或明确的物理逻辑表达。
- 值视图不必每帧深复制世界。可返回标量副本或有明确生命周期的借用接口；Array／Dictionary 含嵌套引用时要隔离，不能只读外壳、可写内部。
- 表现缓存必须可丢弃、可重建，不写回规则。Godot 物理插值只影响显示；传送、重开等不连续点按引擎接口对齐，不默认自建插值或第二个坐标系统。

## ARCH-05：定义、参数与运行状态分开

共享 Resource 描述内容与默认参数，不保存实例进度。边界完成加载、合法性与交叉约束校验，再把所需数值投影给规则、输入、物理与表现；规则不依赖配置路径、Inspector、文件格式或指纹实现。

默认启动冻结参数，重开不悄悄换版本；若启用运行期切换，在安全边界完整校验和原子应用。玩家偏好独立保存，不能反写设计基线。稳定内容 ID 不使用本地化名称或内存地址。参数发现与时机见 [调参导航](../../tuning/README.md)。

## ARCH-06：时间、随机与更新顺序显式

- 引擎唯一负责帧和物理调度。物理相关推进使用 `_physics_process(delta)`，离散输入按约定消费一次，持续输入作为状态；不再复制固定步累加器。
- 规则只消费显式秒数／回合动作，明确零、负数、非有限值与大步长处理。规则计时不读 Time 或真实睡眠。
- 暂停决定哪些节点继续运行、哪些物理／规则冻结；继续不补暂停时间。失焦、最小化、休眠策略需单独选择和验证，不能默认为已覆盖。
- 需要确定的输入、移动、交互、碰撞与规则顺序必须在协调层／物理回调顺序中明确；同处 SceneTree 不自动保证想要的先后关系。事件中读取的是哪一时刻的位置也要说明。
- 新增玩法随机时显式提供种子或可恢复状态，表现随机流分开，规则不从墙钟偷偷重新播种。没有随机需求不先造随机管理器。
- 同一构建、参数、初始状态、输入和推进顺序的复现有环境边界；Godot 物理与浮点不承诺跨平台位级一致。

## ARCH-07：副作用与恢复按需启用

规则不做加载、存储、网络、持久日志或真实等待。外围负责副作用、失败提示、取消和有界诊断。资源由所有者释放；借用节点不释放，RefCounted 也不自动管理借用 Node 的寿命或打破循环引用。部分初始化失败同样清理已经取得的资源。

未启用存档／完整快照时不预置序列化框架。启用后需包含所有影响未来结果的状态：规则计时、进行中动作、等待顺序、随机进度，以及由引擎拥有而恢复所需的物理状态。明确版本、参数兼容、失败后保留旧数据和表现重新对齐；诊断快照不是完整恢复载荷。

完整性以不中断分支和中途恢复分支**逐步比较**验证，不只比较终点；删除实际关键字段的反例必须失败。不为制造反例凭空新增队列／随机机制，不凭逻辑分离承诺跨端物理确定性。

## 审查与验证

- 规则直接构造和显式推进，无窗口／文件／设备；正常、拒绝、边界、重置与时间非法值有测试。
- 同一规则只有一个执行处；物理只有一个位置所有者；表现视图变更不回写规则。
- 重复呈现、显示重建和省略反馈不改变规则、位置、时间、参数、诊断轨迹或生命周期。
- 实际场景验证 InputMap、信号、物理、暂停／继续和反复重开；实际产物另验证 OS 输入与可见结果。
- 完整恢复仅在启用时测试；性能独立测量；审查依赖方向和所有权，不能以源码扫描或无头绿灯代替全部证明。
