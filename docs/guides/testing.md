# 测试与验证

测试回答客观约定是否成立，不为审美、趣味或主观手感评分。测试存在、代码可编译、场景可加载和实际产物可玩是不同证据。架构边界见 [游戏架构](game-architecture.md)，具体命令见 [README](../../README.md)。

## TEST-01：规则在 Godot 无头环境直接测试

使用 GdUnit4，直接构造 RefCounted 规则、有效参数与语义请求，显式推进时间。不创建窗口／音频、不访问 Input、文件、网络、真实时钟或玩家目录，不用大量引擎 mock 掩盖边界问题。

无头仍运行 Godot，不是独立语言解释器。场景物理、资源加载和 UI 单独分类；不能为了“纯”而在测试里复制一套运动或碰撞。规则测试不靠 sleep、真实帧率或其他用例残留驱动。

## TEST-02：从快到慢，证据分层

| 层 | 验证 | 不能证明 |
| --- | --- | --- |
| unit | 规则、边界、拒绝、参数与诊断值隔离 | 场景接线、像素、OS 输入 |
| scene | 磁盘重载、owner、资源、信号、物理、语义输入、生命周期、表现只读 | 真实键盘、GPU、声音 |
| negative | 失败、加载错误、超时、零测／跳过与损坏报告被拒绝 | 所有产品故障已覆盖 |
| product | 实际导出包、平台输入、结果、退出和局部实际像素 | 所有设备／视口或完整视觉正确 |
| 性能／长跑（按需） | 目标设备与配置下的预算、长帧、容量和稳定性 | 其他设备性能 |

每次相关修改先跑定向／快速层，再执行实际产物验证。完整交付由 `export` 串行生成，`verify` 只读复核；缺必需证据、失败、过期、零测试或必需跳过均不能完成。纯文档任务检查链接与一致性即可。

## TEST-03：断言契约而非锁死现状

至少覆盖正常、边界、重复、正常拒绝、非法数据、重置，以及受影响的时间、暂停、恢复和操作顺序。使用给定 → 行为 → 结果，预期来自契约或独立推导，不用被测公式生成答案。

拒绝应断言未修改的状态和没有成功事实，不仅断言返回码。值视图／诊断快照应验证修改返回内容不会污染源状态。表现应验证重复呈现、显示重建不改变规则、物理、参数或生命周期。

缺陷先留下失败回归，失败证据保留。禁止删断言、放大容差、自动更新预期、无条件重试刷绿。涉及随机时记录种子、输入和首个偏差步骤；没有随机不为测试新增机制。

## TEST-04：恢复与复现不夸大

种子或近期动作轨迹不等于完整回放。复现需要构建、有效参数、初始状态、输入顺序、实际推进时间，以及影响玩法的随机／外部结果。

启用完整快照后，用同一输入跑不中断和中途保存恢复两条分支，逐步比较权威状态与下一步所需进度，报告首个差异；删除实际关键字段后同一检查必须失败。只比较终点会漏掉中间偏差。诊断投影不得冒充完整存档，不为凑字段新增队列。Godot 物理的跨平台确定性需另证，不由规则测试推出。

## TEST-05：场景与产品验证结果

- 场景测试从磁盘加载，核对资源、owner、信号、暂停和重开；等待引擎 physics_frame／process_frame，不把真实睡眠当推进。
- Input.action_press 验证语义链路，不证明 OS 输入。产品测试经真实输入路径观察规则或物理结果，不能仅断言“进程未崩溃”“截图不同”。
- 可使用只读探针关联状态，但不能绕过输入直接注入成功状态。开发探针不作为正式包任意写接口。
- 启用的持久化需重新启动后验证；音频／权限／窗口／焦点按目标平台实际检查。没有环境写明未验证，不降级成模拟后声称通过。

## TEST-06：实际画面与性能分开

截图必须来自实际产物，按声明场景核对元素、位置、颜色／对比度、可见性和同帧状态；动画／转场按需采集连续帧。任意两帧不同可能只是背景变化，文件存在也不证明目标画对。

容差来自取整、抗锯齿与明确的平台差异，不为消除失败而扩大。更换玩法、几何、视口、字号或语言时同步判据；不要保留只适用于示例的验证。

性能使用同设备、配置、场景、参数和窗口独立测量，标明 CPU／GPU、预热、样本和预算；截图编码耗时、无头运行或 CI 耗时不能当 GPU 性能证明。主观体验作为独立反馈，不取消客观输入或视觉验证责任。

## TEST-07：工具本身也要失败自证

正式报告来自新进程。核对退出码、日志、完整测试清单和数量、失败／错误／跳过／flaky、报告存在性与新鲜度。故意断言失败、脚本解析／加载错误、资源丢失、超时、零测、跳过和损坏报告必须得到拒绝，不能仅以命令返回零为绿灯。

报告、源码、有效参数、产品和图片需要身份关联。哈希不是签名；不能修改旧报告配合新源码。当前检查的具体范围见 [CONTRACTS](../CONTRACTS.md)。

## TEST-08：自动化与玩家数据隔离

测试、负向检查、导出探针和故障构造使用一次性项目、profile 和数据目录，产物留在 `artifacts/`。不读写真实玩家进度、设置或诊断留存，不将测试材料当玩家恢复材料。

新增持久化或平台入口时复核隔离是否覆盖实际产物，不仅检查单元测试。需要首次运行、损坏或权限失败状态，在一次性位置构造；不要清理或覆盖玩家数据来“准备测试”。失败记录不覆盖，latest 指针可能是旧结果，必须核对当前源码。

## 交付

提供准确命令、报告目录、实际范围与未运行原因。参数与体验从 [tuning](../../tuning/README.md) 进入，发布限制见 [STATUS](../STATUS.md)。核心测试、场景、真实平台、技术视觉和性能逐项说明，不把所有检查压成一句“测试通过”。
